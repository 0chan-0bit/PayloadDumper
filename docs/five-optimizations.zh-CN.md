# 五项优化实现与验证

1. **提前校验**：分区最后一个操作完成后，在当前 worker 内对无需重建 verity/FEC 的分区校验。完成计数器使用原子读改写，发布此前所有操作写入；不额外创建线程。需要 verity/FEC 的分区和零操作分区仍走最终校验。
2. **XZ 复用**：每个线程保留一个 lzma_stream，重新调用初始化函数前清除输入/输出缓冲状态，在退出线程时 lzma_end。依据本机 /usr/include/lzma/base.h 的复用契约；实际能保留多少分配由 liblzma 决定，不声称所有内存都能复用。PD_PROFILE 模式用分配回调统计。
3. **操作成本排序**：保留四分之一大分区优先、其余小分区优先；各分区内部按输出字节×成本权重稳定降序（零操作0、原始/复制1、ZSTD 2、其他4）。这是可验证的粗略启发式，不是已测得的解压时间模型。小于4 worker仍保留原顺序。
4. **零区域**：无源镜像时，ZERO/DISCARD 保留新建截断文件的零区域，省去 memset/pwrite。增量有源镜像时保留原清零。先统一验证所有目标 extent 边界及跨操作/操作内部不重叠，确保跳过写入不会保留其他操作的数据。
5. **线程池等待**：parallel_for 不再让调用者参与，也不使用 yield 自旋。后台最多配置数量的 worker 执行，调用者用条件变量等待所有 helper 完成。异常在等待完毕后传播到调用者。

附加验证：调度测试覆盖竞争领取的唯一性、成本排序稳定性、忙碌 worker 的剩余操作接管；线程池测试覆盖实际执行线程数、不使用调用线程、异常传播后仍能复用；端到端测试覆盖目标越界/重叠提前拒绝、各种压缩及增量/verity/FEC路径。

PD_PROFILE 的 worker_s 是各操作墙钟耗时累加，可相互重叠，不能当成进程 CPU 时间；提取阶段耗时包含内部校验。该版本未安装 perf，没有采样级 CPU 调用栈数据。

## 同场基准

相同 payload、默认校验、-q -c 12、全新输出目录；每次计时前顺序读取全部输入，驻留率均100%，预热不计时。各跑一次，旧版本先跑。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 墙钟时间 | 23.457 秒 | 22.755 秒 |
| 累计CPU时间 | 222.056 秒 | 217.146 秒 |
| 输出吞吐 | 552.4 MB/s | 569.5 MB/s |

单次耗时下降 2.99%。不能用单轮结果断言统计显著收益，也不能从组合结果归因到某一项。
历史逐操作版本曾测到21.874秒，本次新版22.755秒并未超过该历史最快单次结果；桌面负载和回写状态未锁定。
67个镜像独立SHA-256与原始基准、之前版本及本次旧版完全一致；测试图像自动删除。

构建和测试：make -j12 test，93项端到端检查通过，另有调度及线程池并发/异常测试通过。
原始记录位于 benchmarks/five-opt-before-12 和 benchmarks/five-opt-after-12。
